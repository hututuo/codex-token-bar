# Codex Token Bar v0.7.3

v0.7.3 聚焦双端长期运行稳定性、后台开销和 Windows 桌面体验。Mac 继续使用原生 Swift App，Windows 继续使用 Tauri + React + Rust App。

## 更新亮点

- 双端进一步统一数据来源身份、窗口生命周期和缓存提交边界，避免来源切换、迟到异步结果或旧缓存覆盖当前可信状态。
- Swift 在无可见界面时暂停高成本后台刷新，并利用官方未读状态减少完成日志扫描；状态栏刷新与会话缓存清理也更加节制。
- 用量图的横向滚动、整窗翻页和可访问性语义得到修正，键盘与辅助功能能更准确地表达当前窗口和导航方向。
- Tauri 托盘新增原生状态面板，并将实时速率迁移到共享原生流；面板开关、失焦、取消和跨屏定位的竞态得到收束。
- Windows 支持真正的隐藏自启动，并通过常驻单实例激活监听恢复既有主实例；不会为后台启动额外创建隐藏 Dashboard。
- Provider Repair 加强命令互斥、备份与恢复事务、并发复制和失败回滚，降低修复过程中覆盖新数据或留下半完成状态的风险。
- 应用级更新监控每 4 小时自动检查一次，只缓存并主动提醒，不会自动下载安装；手动检查、提醒去重和用户确认安装共用同一个单飞状态域。
- Windows 文件身份与删除字段处理兼容更多系统返回形式，降低新版 Windows API/文件系统差异导致的误判。

## 发布边界

- 本文件随 v0.7.3 源码候选准备；版本尚未发布，安装包、签名、更新元数据和远端 Release 仍需完成发布门禁。
- Windows 最新源码仍需在目标 Windows 环境完成 x64/ARM64 编译，并对已安装应用的系统通知、托盘提醒、隐藏自启和单实例恢复进行真机验证。
- macOS 仍需对 Swift 与 Tauri 两端做候选运行检查。最终资产生成前不会更新 Sparkle appcast、Windows updater metadata 或稳定下载名。
- Windows 安装器仍未使用商业代码签名证书；正式资产若保持这一边界，SmartScreen 可能显示未知发布者提示。
- 实时速率是工作强度估计，不代表精确吞吐；本地使用量、会话、额度、重置卡和雷达数据不会作为遥测上传。

## English

# Codex Token Bar v0.7.3

v0.7.3 focuses on long-running stability, lower background cost, and a more reliable Windows desktop experience. Mac continues to use the native Swift app, while Windows uses the Tauri + React + Rust app.

## Highlights

- Further aligns source identity, window lifecycle, and cache commit boundaries across both apps, preventing source switches, late asynchronous results, or stale caches from replacing trusted current state.
- Reduces Swift background work when no interface is visible and uses the official unread state to avoid unnecessary completion-log scans; status-bar refreshes and session-cache cleanup are also more bounded.
- Fixes usage-chart scrolling, page-sized navigation, and accessibility semantics so keyboard and assistive navigation describe the visible window and direction more accurately.
- Adds a native Tauri tray status panel and moves live rate onto the shared native stream, with tighter handling for toggle, blur, cancellation, and multi-display positioning races.
- Adds genuinely hidden Windows autostart and keeps the single-instance activation listener alive so an existing primary instance can be restored without creating a hidden Dashboard.
- Hardens Provider Repair command exclusion, backup/restore transactions, concurrent copying, and rollback, reducing the risk of overwriting newer data or leaving partial repairs.
- Adds an app-level update monitor with a four-hour automatic cadence. Automatic checks only cache and proactively present availability; they never download or install. Manual checks, notification deduplication, and user-confirmed installation share one single-flight state domain.
- Improves compatibility with Windows file-identity and delete-field variants returned by newer system APIs and filesystems.

## Release Boundaries

- This document accompanies the v0.7.3 source candidate. The version is not published yet; installers, signatures, update metadata, and the remote Release remain gated.
- The latest source still requires x64/ARM64 compilation on the target Windows environment and installed-app validation of system notifications, tray presentation, hidden autostart, and single-instance restoration.
- Candidate runtime checks remain for both the Swift and Tauri macOS apps. Sparkle appcast, Windows updater metadata, and stable download names will not change before real assets exist.
- Windows installers still do not use a commercial code-signing certificate. SmartScreen may therefore show an unknown-publisher warning if that boundary remains for the final assets.
- Live rate is a work-intensity estimate, not exact throughput. Local usage, session, quota, reset-credit, and Radar data are not uploaded as telemetry.
