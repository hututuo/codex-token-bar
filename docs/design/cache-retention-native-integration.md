# 缓存续问建议：原生接入

2026-10-15；源基线 aae3d17919a34d34ba7237940bc35bfcc27e3ca8，分支 `codex/cache-retention-density-20261015`。当前主消费索引实库 schema 14，接入不升级或写入该库。

用户本轮选择：全部本地 owner 混合，排除子代理；fork 仅排除继承部分；主图统一密度配色；一张图同时展示展开的前五分钟与完整长尾；提醒和主页两个入口，使用通俗建议文案。

## 一条数据流程

现有可信来源发现与 CodexRolloutReader → 原始轮次采样及现有 PaginatedHistoryBoundary 自有性证据 → 独立 SQLite 诊断库原子保存源代际、完整行 checkpoint、紧凑轮次事实与相邻配对 → 纯函数 P95/下降拟合 → 同一份 ObservableObject 快照供主页入口、图表和低命中提醒读取。

诊断不读取 latest-turn 投影作为首次 usage，不修改计费 events，不请求模型或上传日志。一个后台写者和一个待处理刷新标记；切换数据源立即清空旧展示并取消旧任务。无变化的来源不重新解析；筛选计算复用同一个纯函数。

## 读取、保存与恢复

日志完整行锁定首次 usage，即使无效也不能换后条。两轮先保持原始相邻关系，再检查完成、模型、首末用量、80% 上轮资格和排除原因。继承边界复用生产代码；不能跨继承前缀或坏轮补连。

独立诊断库保存紧凑 Codable 轮次事实与状态（无提示词或回复）、当前源代际、已提交解码 offset、完整已提交前缀 SHA256 及配对投影。追加前验证完整旧前缀摘要，匹配才只解析新增完整行；截断或内容变化从新代际重建。压缩读取沿用原生 reader。批次让出后台执行权；完整源验证成功后在同一事务切换事实、配对和 revision。失败保留原已验证源，显示未完成，不阻断消费统计。未知诊断库版本停止写入。2026-10-16 起，源删除只标记缺失、保留数值；同路径重写保留历史 generation，并按稳定身份去重。统一契约见 [数值索引保留与发布](ledger-preservation-publication.md)。

同 session 的稳定 UUID 前后轮次及数值证据一致时去重，冲突不任选一份；synthetic ID 仅源内有效。模型/日期范围先筛原始点再拟合，旧范围作业不得覆盖新范围。无结果不回填固定分钟。

## 展示和实时提醒

单图展示按准确计数着色的原始散点；0–80 分钟等比例铺开，每10分钟一格，仅80分钟后通过一个双斜杠标记压缩长尾，保留全部点。计数网格固定 10 秒 × 5 个百分点，共用对数色标。图内标明比例变化；不平滑或抽样。

先用原有单调 1/2/3 段拟合与 BIC 惩罚找到全局最大下降，作为第二条低命中风险线；再仅对这条边界之前的数据应用同一拟合，取其中最大的受支持下降，作为第一条建议续问线。第二次拟合不递归，不设必须下降 10 个百分点等幅度门槛，也不输入期望分钟数；同一时间的点保持分组。若早段只支持一段，就不补画第一条。建议线显示“建议尽量在约 X 分钟内续问”；另一条显示“超过约 Y 分钟后，低命中更常见”。两者是当前本地历史参考，不称物理截止时间。P95 仅保留为历史高命中样本的时间覆盖补充，不能称为推荐等待时间或成功率。

现有低命中条件（输入 ≥20000、命中 <30%、非新上下文首请求）保持。通过现有 live rollout 读取附带任务开始/完成边界，展示实际空闲间隔；缺证据就显示暂未取得。提醒提供明显“查看间隔图表”按钮。主页在实时监控附近放建议摘要卡，同按钮打开同一图表，不另建提醒专用计算路径。

## 0.9.5 双端实现与建议稳定性

Windows 的对应链路为 `session_parser/cache_retention_parser.rs` → `cache_retention/database.rs` → 受 source token 约束的命令 → `cacheRetentionClient.ts` → 共用 React 图表与提醒入口。重用生产 fork 所有权判断，不能从“最新 usage 的轮次汇总”反推首次 usage。原始会话内容不写入诊断侧库。

早期建议的模型阶数仍按 BIC 选择；在所选两段模型中，对 ΔBIC ≤ 2 的相近支持候选取高命中比例下降最大的边界，同幅度取更早位置。这是对近似等价候选的选择规则，不固定为 15 分钟，也不要求下降达到 10%。风险线和 P95 保留原本含义。Swift 与 TypeScript 使用相同边界、同样的整数高命中判断及相同合成扰动回归。
