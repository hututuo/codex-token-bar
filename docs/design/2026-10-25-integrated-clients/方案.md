## 1. 总体结构：一个范围，整页切换

保留头像、工具栏、额度条、Token统计、模型费用、雷达、速度、活动图、24h图和排行的原有位置与风格，不新增独立客户端用量大卡。

**主内容左上角放一个较大的原生分段开关：`Codex / Claude Code / 汇总`。** 默认Codex；客户端较多时扩展为 `Codex / Claude Code / 更多… / 汇总`，更多菜单内只做单客户端选择。“汇总/分开”两段还要再选客户端，反而多一步，因此推荐直接列名称的方案。

所有数据模块使用同一个范围：Token、模型与费用列表、活动图、24h/7d/30d图、TPS、额度及排行一起切换。删除模块单独范围、“跟随全局”、“自选客户端”、“全部跟随”及相关设置入口，不保留暗中的模块覆盖。图表内切总量/来源分线仅改变绘制方式，不改变来源集合。既有模块显示/隐藏、样式等设置仍可保留，不能再藏第二套客户端范围。

同一个范围也用于三级菜单展示的来源过滤；侧栏额度列表=用户勾选项目与当前范围的交集。汇总时能看到勾选的多客户端额度，单看Codex时不混入Claude。一级、二级、三级不用再放独立范围开关；不能出现三个层级分别在看不同来源。切范围只改变显示，不启停采集、不删除历史、不自动开启上报或联网额度。

切换时统一数据版本，先显示明确加载态，不先换标题再冒充显示上个范围的数字；缺失来源显示—/未提供，汇总不完整时标“部分”。只有Codex才支持的动作如会话修复/重置卡继续标明Codex，单看其他来源时收起或禁用，不能冒充通用功能。

范围选择持久化，首次仍为Codex。发现新客户端只在原工具栏旁提示一次“发现Claude Code · 启用”，可忽略，不弹大窗。未启用客户端名称可在首次提示旁禁用显示，启用后才能选；剩余旧目录只称“发现本地记录”。隐藏模块不删除数据，禁用来源停止后续扫描，历史仍保留。

## 2. 各原模块怎么切

| 原模块 | 单客户端 | 汇总 |
|---|---|---|
| Token 数及输入/输出/缓存/思考 | 选定来源的本地已记录量 | 同一时间范围内相加，详情可按客户端拆分；不完整时用短标记「部分」 |
| 模型费用/价格列表 | 只显示该客户端的模型 | 同一位置列出 Codex、Claude、Gemini 等模型，模型名旁有小客户端标签，可按客户端分组；不另开大卡 |
| 峰值/会话最大/连续天数 | 保留原含义 | 峰值由合并后的时间桶重新取最大；会话最大取各会话最大值；连续天数按有活动日期并集重算，不能直接相加 |
| 活动图、24h/7d/30d 用量图 | 原图展示该来源 | 同一张原图，默认总量线；「按客户端」显示来源分线，悬停同时看总量和各来源；不复制几张图 |
| 实时速度 | 该来源现有可用活动速率 | 相同口径、同一时刻的并发输出速率才可相加；未知来源不补0，标出覆盖范围 |
| 正文TPS明细/5、15、30分钟均速 | 按来源过滤有效样本 | 按客户端+模型保留归属；同口径按总有效输出Token÷总有效输出时长计算，不能把若干TPS简单平均 |
| 额度 | 相应账号的独立窗口 | 同一区域并列多个额度，不提供“总剩余百分比” |
| 缓存命中排行 | 有可靠缓存字段时显示 | 按总命中输入÷可比较总输入加权；字段缺失的客户端显示未提供，不将未知当未命中 |
| Codex雷达/重置卡/会话修复 | 保持Codex专属标记 | 不因全局范围变化将Codex专属功能误标为全客户端；菜单动作仍明确作用来源 |

### 时间与价格

- **24h图沿用5分钟桶，7d沿用1小时桶，30d沿用6小时桶**，与当前原图一致；不沿用上一版新增大卡的小时/天桶。各客户端统一时间边界、本地时区显示，跨日和夏令时用实际时间戳对齐。缺失历史显示断档，不把未扫描、尚未完成索引视为0。
- 支持字段按可用性显示，例如某来源没有思考Token，就显示未提供，不估算一份凑总数。
- 单客户端且账号明确时保留「本期」。跨客户端汇总默认用「今日 / 7天 / 30天 / 自定」等共同时间区间；不把不同订阅起止的多个“本期”直接叠加。用户仍可明确选择“按Codex本期日期查看所有来源”，那只是共同日期筛选，不改变Claude订阅周期。
- 同模型在不同客户端中不丢来源。价格按供应商、模型版本、缓存读写类别及生效版本匹配；覆盖不全则显示「已知模型估算 $… · 部分未计价」。不可计价的模型仍列Token，不能显示$0。
- API价格折算与实际扣费分开：本地Token日志不能证明订阅扣费、抵扣或最终账单。不把多个客户端的订阅成本、净收益强行套用原Codex套餐。汇总时相关字段显示可核算部分或—，说明放悬停详情。

### 两种测速必须分清

原有正文TPS与 Agent Speed 独立采集/上报是不同口径。整页切换客户端时也不能把两套测速混成一个平均数；速度区域保留明确的小口径选择/标签，原值、过滤规则及上报开关均不改变。没有正文起止数据的客户端显示「暂无可用样本」，不能拿Agent Speed值填入正文TPS栏。没有活动事件支持时也不能凭Token结算记录伪造实时波动。最终采样是否覆盖某客户端，以测速分支实际能力为准，界面不承诺尚未采到的数据。

## 3. 额度：分别设计三个层级

### 3.1 公共设置与计数规则

在原“侧栏设置”逐项勾选，例如Codex·5小时、Codex·7天、Claude·5小时、Claude·7天；支持原额度填充颜色、顺序和外观选择；客户端识别圆点统一采用下述品牌色，不随机分配。默认保持现有Codex显示，Claude用户主动选入。显示设置可分别控制一级/二级的额度项，但每层来源都遵守唯一全局范围，不能另选客户端。

“一项”是 **提供者+账户+额度窗口**，不是客户端数量。例如同一账户5小时与7天算2项；Claude Code/Desktop共享同一订阅则共用提供者，不算两份额度。没有账号归属时明确未绑定，不能伪造多账号识别。

全部已选额度按用户保存的顺序显示；明确选入的“未接入/过期”项目也保留并显示—。尚未提供的假设窗口不自动出现、不计入数量。不再按数量制作示例图；不因项目多而自动隐藏、折叠或替用户选重点。

### 3.2 一级菜单：完整额度条+品牌色圆点，全部项目自适应

**不限制最多几项。用户勾选多少额度就显示多少，按用户排序保留所有项。** 删除旧的“最多4项+角标”、自动重点筛选、分页收纳规则。一级保持原版约16pt黑色贴边窄竖条、约4pt纵向轨道、边缘平直/朝桌面圆角，保留速度与模型占比条；不加宽、不横排、不旋转文字、不自动轮播。

#### 每项额度是一根完整条

- **一项额度=一根连续轨道**，沿用原版单根竖条；不能为了区分客户端/窗口切成小段、色块、虚线、点阵或马赛克，也不能把几个客户端拼到同一根额度条里。
- 客户端识别只用条旁/邻近的小圆点。圆点与额度轨道独立，不嵌在条内、不打断轨道，不挤宽原16pt侧栏。圆点位置随条一起布局，在设置、悬停说明和详情里有对应客户端名称。
- 有读数时沿用原版一段连续进度填充及剩余底轨；正常填充边界不等于把一项拆成多个片段。填充颜色继续按原额度显示设置，不能为客户端识别加多色拼接。
- **无读数时也是连续完整的灰色底轨**，不要再用虚线/断续小块代表未知。展开后显示未接入/不可用/已过期等文字；未知不能冒充0%或100%。
- 速度条与模型占比仍是原有独立模块。本次对“额度条不分段”的要求不改写之前模型速率贡献/模型用量组成的规则。

#### 长度设置

在原“侧栏设置”增加一个持久化选项：**竖条长度：长条 / 短条 / 自动**，默认自动。选择只影响几何长度和间距，不影响数据、百分比、速度算法、项目数或顺序。长/短形态的速度条、额度条、模型占比条统一适配，速度和模型占比不计入额度项数，但都计入总高度。

| 模式 | 首选表现 | 高度不足时 |
|---|---|---|
| 长条 | 原条长约46pt，间距约12pt | 保留所有项，在当前屏幕可用高度内继续收紧布局；手动选长条不是允许超出屏幕 |
| 短条 | 设计首选条长约24pt、间距约8pt | 保留所有项，仍按实际可用高度缩放 |
| 自动（默认） | 先计算完整长条所需总高 | 超出原推荐高度约20–30%即切短条，默认采用25%；不是超过某个项目数就隐藏 |

长条46pt和间距12pt来自当前原组件；短条24pt/8pt为本方案建议值，待实现时视觉验收。菜单内只提供三种模式，不追加复杂阈值控件。

#### 自动切换阈值与高度边界

- `H推荐`：原版收起竖条推荐高度，当前源码至少双额度状态以250pt、单额度以192pt为基线。基线不随更多额度数量继续增长，否则永远触发不了超高判断。最终外框按可见内容实际缩小，隐藏全部额度也不保留额度空位。
- `H长`：**所有**已选额度，连同速度/模型占比、外边距、间距的完整长条总高度。
- 默认触发：`H长 > H推荐 × 1.25`，即超出约25%；20–30%是设计容许范围。以原双额度基线250pt演算时阈值为312.5pt；当前效果图不再画数量/尺寸对比。
- 判断始终用完整长条测量值，不以短条测量值反向判断，因此不会自激闪烁。本版未增加20%恢复回差；仅在项目或显示模式变化时，按同一个25%条件重新计算。
- `H可用`：当前贴边显示器工作区可用高度，已扣除系统栏/安全边距。**任意模式的最终外框不得超过H可用。** 长条还没到25%阈值但已经放不进工作区，也必须先适配物理高度。
- 短条还放不下时继续按高度收紧长度与间距，所有项目仍保留。极端到每项不足最小可辨像素时，让全量内容在有限高度内滚动，而不是删除、角标代替或限制最多N项；这属于物理边界的兜底，不是默认收纳方案。
- 切换屏幕、工作区高度变化、勾选/排序项目、切换模式时才重新测量；不因TPS每秒数值变化重复布局。高度伸缩使用短过渡，减少动态效果时直接更新。

## 4. 数据与统一接口：实现时的约束

- Token仍按客户端、模型、来源事件、时间保留独立事实记录；界面范围只是投影，不迁移/覆盖原Codex账本。原始删除保留统计历史，未知字段保留null。
- 合计Token=输入+输出；归一化输入含已报告缓存读写，缓存是输入子集，思考通常是输出子集，不重复累加。请求次数若来源无法提供则未知。
- 跨客户端镜像日志仅在可证明是同一原始事件/请求时去重；相同模型名不等于重复，也不能把同一harness被两处扫描重复记账。无法确认的覆盖问题给出诊断，不能承诺任意日志精确全覆盖。
- 统一QuotaProvider返回 provider、账号归属状态、窗口ID、已用/剩余、重置时间、观测时间、来源和可用状态。Codex复用现有观测；Claude只投影已有本地缓存；网络提供者 capability 明确禁用。UI渲染不会触发请求或读取凭据。
- 不为每个模块新开扫描/定时器；共用一次快照，切范围时复用聚合、缓存按唯一全局范围/时间区间/数据revision失效。图表仅准备可见窗口；Token历史不跟TPS每秒重算。
- v7已从原始带时间戳事件直接聚合5分钟UTC桶，再投影24h/7d/30d图，不均摊小时数值。包含两端未满桶，另有365个本地日历日聚合（覆盖夏令时）。只读聚合不改变v2账本schema，不需要升级迁移；原Codex账本不改写。
- 模型API等值按单次请求定价后相加；采用随源码固定的离线价目表，不开启测速上报。未知模型、需要缺失生效时刻/缓存写入寿命等无法确定的价格规则不计价。未知缓存读数的请求不进入命中率分母，不能当零命中。
