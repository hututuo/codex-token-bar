- 客户端原始文件、旧账和用户导出不修改；既有正式版不安装、不替换、不重启；Claude不发网络请求。
- 测试分支可进行实现与云端验证；不合并main、不触发签名／发布、不恢复撤回的更新源。测试工作流需先核对事件与权限。

- 每批只提交本批代码／测试／报告。仓库中已有撤回记录、调查ZIP、他人改动不混入修复提交；不使用`git add -A`。

实现边界：只增加一个专属pool namespace和必要的受限发布桥；保留A根合同、Exact主schema和parser规则。六表具体约束／版本／codec先由同一fixture校对，再接生产writer。

1. 固定module与logical identity，首建DDL和注册在同事务完成；pool独立于旧stage枚举。未知pool版本只暂停相关新写入。
2. 按job保存来源合同、有效前缀、初始parser状态、typed-row与chunk证明。seal保护单个job；不能调用整store seal把pool关成只读。
3. 正式发布桥在同一A writer连接显式绑定目标与pool，提交旧平台原有整轮发布边界和消费回执；不得开放任意namespace SQL。

**故障注入**：pool首建前后、批次提交、seal、正式commit前后、写回执、清理中逐点跨进程退出。结果只能是旧完整代或新完整代；不能一部分正式账配另一部分回执。

**失败处理**：停相关owner的新发布，旧published可读。开发中可回退新增代码，但不得把已写新账的数据库换回旧备份；数据恢复走可读取当前合同的修正版，不宣称旧二进制降级安全。
