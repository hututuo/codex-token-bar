# 升级与运行诊断包

本功能复用现有迁移回执，增加独立的固定字段事件文件和脱敏导出器，不新增业务数据库，不改变安装、迁移、账本或修复的授权与提交顺序。

## 入口与边界

- Swift：设置、帮助菜单、日志弹窗、迁移/失败页均可导出；`CodexTokenBar --export-diagnostics --output <新文件.zip>` 在创建 App 及业务 owner 前退出。
- 独立 Swift `TokenBarDiagnostics` 只依赖 Foundation/CryptoKit；随 App 与 DMG 内 Diagnostics 目录提供，可在主程序损坏或 Sparkle 依赖失败时运行。
- Windows：主程序 `--export-diagnostics` 在单实例准入和 Tauri/WebView 初始化前执行；独立 `tokenbar-diagnostics.exe` 与 PowerShell/CMD 入口随安装包提供。UI 导出到 Downloads，失败时提示离线入口。
- 两端同名探针：environment、events、recovery、installation、storage、legacy、crashes。各探针为独立子进程，默认 3 秒预算，超时后只终止自己的采集子进程。缺失项目写为 unavailable/timeout，不代表系统健康。

## 数据与脱敏

日常事件：版本/build、随机启动/升级编号、序列、时间、固定 area/phase、允许的整数计数。后台进度和 UI 接收分别记为 backendProgress / uiProgress。迁移与发布仅在既有流程观察状态，不额外查询数据库。异常仅保留类别与数值错误码；自由错误文本、请求、路径、认证、会话标题/正文、环境变量和数据库原文不进入新日志。

每次启动独立 JSONL，单文件 256KiB、总预算约 8MiB、30 天/约 120 文件；首个失败另外以小文件保留，重启不覆盖。日志写入异步、队列有限、失败不改变业务结果。已有恢复 JSONL/最近失败按固定字段重建，旧性能日志仅抽取允许的数值字段。原始日志不会直接加入包。

导出前再次执行统一字段白名单投影，包括子进程结果；UUID、版本、枚举及数值分别验证。路径和用户标识不输出；业务库仅取固定目标的文件元数据。所有数据库状态详情来自业务正常运行期间的事件；未记录的旧版状态明确缺失，不通过打开业务路由补全。

ZIP 包含 SUMMARY.md、manifest.json、state/*.json、events/*.jsonl。使用固定归档文件名，拒绝覆盖既有输出。默认不读取内存转储，不上传，不进行网络探测，不自动重启应用或调整权限。崩溃只收集本应用的有限元数据；系统没有记录则 unavailable。

## 升级确认

Sparkle delegate 只观察发现、下载、校验/解包、安装、重启和错误回调；安装前保存独立绑定回执，新版本同一安装位置完成刷新后才确认。安装器已启动与更新检查完成不能代替升级确认。

Windows 沿用已存在的安装目录、目标版本回执与启动确认，补充持久事件及 NSIS 安装开始/载荷完成记录；手动 NSIS 安装开始而没有完成行表示未确认完成，不凭空归因。install.sh 增加持久回执和新版本确认绑定，原有安装政策保持不变。

## 验收

在云端执行真实代码回归：伪造敏感字段/原始路径不进入 ZIP；数据库损坏/加锁时采集不打开也不修改；软硬链接与 FIFO 拒绝；子进程超时能返回部分包；重启保留上轮失败；错误版本/目录不得确认升级；界面导出不调用启动重试/修复命令。最终在候选 SHA 运行完整双端 CI、打包、独立工具与已安装 UI 导出，再替换本机。

历史缺失日志无法重建；诊断包是观察证据，不是自动修复工具，也不是对所有问题的确定诊断。
