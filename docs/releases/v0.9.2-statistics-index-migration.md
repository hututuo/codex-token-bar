## 新统计连续性规则

统计链路的事实身份由规范化路径、session ID、大小、mtime、首尾 probe、4 MiB chunk hash、parser checkpoint、resume offset 和已提交前缀组成。device ID、inode/File ID、卷序列号、Codex Home physical identity 和 ctime 不再参与统计命中、增量或缓存隔离。

- 路径、大小、mtime 相同：直接 `unchanged`，不读 JSONL 正文。
- 文件变大：验证 checkpoint、旧尾块和轮换审计块后，只解析新增后缀。
- 大小相同但 mtime 改变：先比较轻量 probe，再以固定 64 KiB 缓冲流式复核该文件已有 4 MiB chunks；内容一致时不跑 JSONL parser。
- 前缀或 chunk 不一致、文件截断：只重建该文件。
- 新文件：正常首次解析。
- 缺失文件：只有完整枚举成功后，才随新 generation 原子发布单文件墓碑。
- 路径下文件对象被替换但内容完全一致：视为同一份认可数据。
- 已确认越界的 symlink/active rollout 会被安全拒绝并记录警告；真正无法确认路径、权限或 I/O 时，判为扫描不完整并阻止本轮发布。

Swift 与 Tauri 都继续使用从已打开句柄读取、固定 64 KiB 缓冲、最多 4 个 staging worker、512 MiB ready-artifact 上限、source/file generation、chunk、checkpoint、rolling audit 和 suffix parser。扫描期间若继续追加，只提交扫描起点前已验证的前缀，新后缀留到下一轮。

## 迁移与恢复约束

schema 6→7 和 9→10 都只迁移包含旧身份字段的小型元数据表。迁移前检查临时空间；迁移事务内执行行数、外键、events/chunks、aggregate 总量和 generation lineage 对账，失败时整笔回滚。迁移本身不遍历 JSONL。

自动删除式恢复入口已经关闭。identity 漂移、未知 schema、迁移失败、`quick_check` 失败、DB/WAL 收据失配、权限/磁盘/锁/I/O 失败、枚举不完整、staging 恢复失败以及内容 probe/checkpoint 不一致，都只能返回上一份可信数据或 `repairRequired`，不能删除活动库、清空整表或清理缓存 namespace。

仍允许的删除仅限正常成功事务中的单文件旧版本/墓碑、被新 published generation 取代的旧 generation、成功导入后的受控 staging，以及精确白名单中的已废弃 cache namespace。会话删除、Provider Sync、项目移动和未读状态等会改写用户数据的链路继续使用原有 physical identity 保护，不属于本次解耦范围。
