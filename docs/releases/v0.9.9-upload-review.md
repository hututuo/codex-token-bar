## 已授权的操作顺序

1. 版本一致性与补丁来源检查后正常快进推送 main（拒绝覆盖并行提交）。
2. 对精确源码运行全量 CI、公开旧库升级和双端构建。
3. 从 main 调用 `sign-release.yml`，使用现有保护环境密钥，仅签名已验证字节；校验两套签名与资产散列。
4. 从 main 调用 `publish-release.yml`，参数 `version=0.9.9`、`confirmation=publish-v0.9.9`。创建新 tag/Release，上传封存字节，回读核验后最后激活更新源。
5. 远端回读 tag、9 个公开资产、发布说明及两端更新源，记录 cloud locator。下次日志比较起点为 `v0.9.9`。
