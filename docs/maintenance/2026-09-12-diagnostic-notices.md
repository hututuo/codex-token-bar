# 双端简短状态与诊断日志

## 展示与记录语义

主界面正常时不显示日志行和常规提示；错误时才显示简短横幅及日志按钮。设置右侧常驻“完整日志”，点击打开独立面板，不挤占主页面高度。日志区分当前问题与历史记录，可一键复制全部；带首次、最近记录时间、重复记录次数、恢复或错误变化时间，以及原始原因与来源。重复记录次数不代表网络实际尝试次数，底层诊断中的 attempts 字段仍保留。

记录范围明确标为本次运行，历史最多 100 条，不写入用量索引、不触发重扫。退出后本次日志不持久保存；不是 macOS 崩溃报告或完整网络报文归档。当前列表仅表示已采集且未被后续成功解决的问题；空列表不作为应用绝无故障的证明。

日志由数据读取/命令完成路径采集，不依赖是否打开详情页。数据失败仍保留上次可信值的既有策略不变。只在对应操作实际成功时关闭当前问题；错误变化单独标注。跨平台索引升级异常转交处理时标为“已转交处理（不代表恢复）”。过期命令结果不能清除新请求的错误。

## 核查与修复

- Swift 额度静默保留旧值的短暂失败也采集原因，重置卡独立记录与恢复。
- Swift 用量统一 catch 覆盖索引升级、数值成功但会话详情失败及普通读取失败；只有可信精确数据恢复才关闭该问题。
- Swift 历史周期 catch 原来丢弃具体错误；现保留具体原因并在成功读取后关闭。
- Swift 众测的 table/leaderboard 原先 try? 丢掉错误，甚至双源失败只剩 invalidResponse；现在保留失败来源及原因，部分成功 snapshot 携带 sourceDiagnostics；所有源失败保留源列表与对应原因。
- Swift RSS 地址缺失/非法不再当作成功返回空列表，不再因此误关闭现有问题。
- Swift 与跨平台的雷达主页补充倒计时请求失败可查看原因；可选补充失败不会使主雷达数据失效。
- Swift 雷达详情记录真实完成失败时刻，非请求开始时刻。
- 跨平台统一命令异常、成功响应中的 diagnostics/warnings 都进入采集器；众测 endpointErrors 另有采集。
- 跨平台雷达详情在命令成功后解析失败也记录，不再被命令成功清理掩盖。
- 日志默认不出现在主页面文字、可选择复制，复制失败有明确反馈。
