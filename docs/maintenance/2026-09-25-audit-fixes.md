## 变更

- F01：Windows 主窗口与 WebView 子窗口不再加入不符合“同父窗口”契约的 DeferWindowPos 批次。保持 Wry viewport pin，抑制重绘后分别提交，失败恢复原始几何，最后统一重绘并保留浏览器 paint barrier。
- F02：Swift/Rust 的既有文件元数据增加物理标识与 change time。稳定源文件只查元数据，不读取正文、不计算内容哈希；发现替换/改写后进入原有内容校验和账本冲突保留流程。追加仍从检查点增量读取。
- F03/F04：拖动准备失败、原生拖动拒绝、禁用/销毁时释放状态；详情关闭最多尝试三次原生恢复，只有成功才忘记原始位置，后续布局能继续使用保留的恢复基准。
- F05：侧栏按请求编号分别报告接收与最终完成；逐帧失败立即尝试目标终态，仍失败则隐藏，失败回执撤销前端去重状态。旧动画不得覆盖新请求或已关闭的侧栏。
- F06：复用现有“未定价”字段处理有日期、无历史报价的记录，不以当前价格伪装历史价格。缺少日期沿用当前估算；不增加数据库字段、历史重扫或复杂时钟防御。
- 新安装仅启用额度侧栏；已有浮窗、状态栏和明确关闭侧栏的设置保留。Swift 二级摘要原有三个按钮加稳定无障碍标识，以便核查运行包。
- 发布脚本在 npm、测试与构建前核对 Tauri/npm/Cargo 版本，参数不再到产物生成后才暴露版本不匹配。

## F02 存储合同与开销边界

`source_observations` 是可缺省的元数据观察缓存，不是消费凭据或新的账本身份。Swift 以 source_id、Rust 以来源路径定位，并同时绑定既有大小/mtime；字段保存物理标识和 change time。新暂存清单附加可缺省 physical_stamp。原有会计 schema 13、账本、解析器与缓存命名空间不变；旧清单继续接受。

旧索引没有这组观察值时，在正常同步中只补录当前元数据，不把全部历史重新哈希。由此明确存在的边界是：第一次补录之前发生、且所有旧元数据均被保留的改写不能被事后证明；不以全历史扫描代价追补这一未知信息。补录之后（包括重启）即可据物理变化触发复核。

Unix 使用现有 stat/fstat 的 device、inode 与纳秒 ctime；Windows 使用文件句柄查询 volume/file index 与 ChangeTime。记录只随真实处理或旧基线补录写入，稳定刷新不反复更新观察表。保留时间戳的同内容移动可复用数值事实，变化内容保留未决冲突，不擅自清空旧用量。

## 明确不扩展的范围

不实现旧程序读取新索引的降级兼容；旧程序应提示索引版本不兼容，不指导用户删除永久账本。迁移失败时的事务/候选保护仍保留，这是正常升级的数据安全，不是额外的降级功能。

已定位 Swift 正在运行的旧副本为 `Installed-Swift-before-sidebar-refresh-20260913.app`；源码已有固定、刷新、主页三个动作，不能用重复添加按钮替代运行包核验。Windows 引导必须同时核对顶层 HWND、WebView viewport 和实际图文边界，不能只依据 CSS 单测宣称通过。
