# 限定 Rust 五分钟聚合的查询范围

Rust 每导入一个来源都会刷新相关的五分钟统计区间。原查询通过 `files` 兼容视图对整个来源目录计算 `MAX(generation) GROUP BY path`，再连接另一份 `files`；区间很小也会扫描和物化不相关来源。在此前 4,124 来源、503,128 事件测试中，逐来源聚合累计 133.514 秒，包含在 391.860 秒的历史补全中。

本次把区间更新提取到 `exact_usage_index/dashboard_buckets.rs`：先在 current、full pending、delta pending 三个分支内按时间范围取行，然后仅对命中的 `source_id` 检查最新 generation 和删除状态。delta 仍先逐来源分组，再进行全局聚合，保留整数溢出错误和 NULL model 规则。原先的删除、插入和调用者事务保持不变，兼容视图继续供其他调用使用。

`pending_dashboard_source_5m(bucket_start, source_id)` 的新索引与 current 层的时间索引对应。新库和已迁移的当前 schema 初始化时安装；现有库在通过兼容检查、完成会计迁移后幂等补齐。只读打开不安装索引，不提升 schema 或账本版本，不重写已有事件。

本分支基于 `7e9d88d2`，保留之前的旧账恢复、TEMP 隔离、阶段池所有权、消息查询、对账语句复用和 pending 关联索引修复。其他会话正在进行的 API/额度改动没有混入本提交。

## 验证

- 新性能回归在原查询上实际失败：仅更新一个区间，1,024 来源导致 6,138 次 FullscanStep、2,047 行临时索引构建、253,372 个虚拟机执行步。测试时原查询也已获得新索引，证明仅加索引不足以解决整份目录物化。
- 修改后该回归通过：扫描步数小于 64、无自动索引、执行步数小于 10,000；实际 pending 结果为预期值，其他来源和已发布数据保持不变。
- 新增真实 namespace 连接执行、旧库重开补索引、full/delta/tombstone/空替换/未来 generation/上一代可见性、溢出和事务回滚检查。5 个测试均列为 CI 必须实际执行的用例。
- 最终产品 SQL 的完整 Rust 库回归：1,778 通过、0 失败、14 项原有可选未运行；包括 schema 9/10 迁移、历史恢复、中断保留上一完整版本、Summary→Full 和 TEMP 隔离。
- 相关执行报告和工作流脚本测试：30 通过。

本地证据位于 `scratch/rust-swift-performance-20261105/`。原查询失败和修后结果分别是 `before-product-tests.execution.json`、`after-product-tests.execution.json`；完整回归是 `library-regression.execution.json`。调查阶段的 SQL 伸缩实验保留，不能当成整轮产品提速比例。

## 生产路径与耗时

最终产品构建通过；非 `test` 生产入口的 16 个核心场景通过，包括 8 处中断、每处 3 次重新打开。完整规模继续使用 4,124×122 事件、6,250 个旧空候选和原性能门槛。4,124 个输入文件的逐字哈希与原 405 秒运行一致，产品源码在测试前后保持一致。

| 指标 | 前次候选记录 | 本次最终产品代码 |
| --- | ---: | ---: |
| 完整回填（含随后同步和汇总） | 405.514 秒 | **323.102 秒** |
| 20 次无变化刷新 P95 | 1.256 秒 | **2.440 秒** |
| 原始事件/ID/数值/类型摘要保持 | 通过 | 通过 |
| 完整性能准入 | 失败 | **失败** |

这次完整回填少 82.412 秒（20.3%）。前次运行含细粒度诊断计时，本次没有；两次主机负载也未受控，因此这是两次实际测量，不能把全部差值都归因于这一处改动。单条查询的受限扫描回归另有原实现失败、修后通过证据。

回填前后均为 503,128 条事件、2,515,640 tokens、4,124 条补全回执；原始事件摘要同为 `442df884874a33dc15d2c5a07ef61c7aae3a52d35de9863d7459e290e4716e3d`，没有警告，所有旧空候选保留，MAIN 对象和 store 数量在回填期间零增长。

无变化刷新本次 P95 比前次更高，不能忽略，也不能仅凭猜测归因于机器负载。本修改没有改变无变化检查的逻辑，但这不足以证明最终使用体验已达标。`product-scale.validation.json` 明确保留 **FAIL**，失败原因是原定 1 秒 P95 门槛；原始 producer 的顶层 PASS 只代表功能场景完成。原始报告保留为 `product-scale.producer.json`，不改写成准入成功。当前无需为了这个定点修复扩大到另一轮结构改造，后续日常刷新优化应独立定位。

原 405.514 秒由 391.860 秒历史补全、12.903 秒后续同步和 0.746 秒汇总组成。本次测试未追加阶段探针，323.102 秒只按原有合计口径报告。整个测试进程另包含数据准备、旧候选构造、数值校验和后续核心场景，1000 秒的进程总时间不等于用户回填时间。全部失败记录保留，未降低样本或放宽阈值。

Swift 的 185.203 秒计时范围、输入字节和数据库结构不同；它不能作为严格同输入速度比，也不能据此声称安装版已达到同样速度。此修补不解决已记录的 Swift 长写锁。

所有验证使用隔离测试数据；尚未安装、推送或发布。
