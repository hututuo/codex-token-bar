## A. 用户要求与不可破坏的原则

> 已经扫到并保存过，说明这条记录曾存在。后来 OpenAI 重写文件，找不到子 Agent 的早期记录，不能据此清空旧用量。保留历史，但仍需增量更新和有证据的修正。

1. **已观测事实与当前原文分开。** 保留旧事件、原始数值和证明；当前文件缺少该事件只表示原文覆盖变化，不是“从未发生”。这不等于把旧版重复计费或异常记录永久当成正确消费。
2. **保全不是冻结整个库。** 新调用持续增量入账；新证据可补充模型、时间或关联；明确旧重复/错误时作可追溯修正。不能仅凭“解析结果减少”删除旧事件或以维持总数单调掩盖错误。
3. **三种变更必须独立表达：** 新增消费、重新关联原文定位、修正既有入账。单纯重建缓存不是新的消费或旧消费撤销。
4. **兼容两个维度：** v0.9.1 及本轮已分发中间索引；旧 legacy 和 OpenAI 转写后的 paginated 原文。格式迁移和会计修正不能互相替代。
5. **先保全后解析/替换。** 首次打开的自动维护、修复、tombstone、清缓存等路径也必须遵守，不能保护函数尚未执行就先调用现有 full replacement。
6. **归属不猜。** 子任务同时识别 `source` 的 SubAgent 枚举和 `thread_source=subagent`；展示前缀不等于父任务消费；缺模型/时间/组件不编造费用或精确周期。
7. **性能保持增量。** 健康文件不重读正文；结构升级从 SQLite 导入，原文解析为零；确有语义重写只对受影响来源定向对账，单次扫描可恢复，不循环全库重扫。
8. **账本不保存聊天全文。** 长期保存逐调用数值、必要时间/模型/关系/身份和去重证据；图表、排行、扫描位置及正文摘录是可重建缓存。
9. **同一用户的双端行为一致。** 两端可独立存储，但兼容、计数、修正、补差语义与测试样本一致；不能只在一端保护旧账。

## D. 来源状态与事件保留规则

| 观察到的变化 | 分类和动作 | 旧账处理 |
| --- | --- | --- |
| 验证后正文未变 | unchanged；不解析、不推进事件 generation | 原样保留 |
| 前缀/尾块及计数状态匹配，只新增后缀 | append；延续检查点并事务追加 | 保留旧事件，新增只记一次 |
| legacy→paginated、截短、重排、内容证明失效 | rewrite/reconcile；新来源代际，记录识别证据及原因 | 先保存全部已发布事件；匹配新原文只更新关联；缺席事件仍在 |
| 来源变了但无法证明原因 | changed-unresolved；与已知 rewrite 分开 | 同样先保留旧账，不要求证明是 OpenAI 才允许保护 |
| 文件移动/归档 | 身份与内容证据建立关联，更新位置 | 不删账、不复制消费 |
| 文件暂时缺失/不可读/坏 UTF-8 | unavailable；记失败范围，有限重试 | 保留历史，其他来源继续工作 |
| 有证据证明旧继承重复或计算错误 | explicit correction，关联证据与算法版本 | 保留原事实，调整有效入账并记录原因 |
| 用户明确清除统计历史 | 独立用户动作，清除指定范围及受管恢复材料 | 可以删除；普通删聊天/清缓存不等同此动作 |

检测不能仅靠 size/mtime：已知上游可以保留 mtime，内容可能被等长改写。利用平台可用的文件替换信号、格式头、checkpoint/probe/chunk 校验识别变化；具体证据不足时进入 changed-unresolved，不强行断言原因。探测只对变化/需验证来源按既有增量预算执行，不能每次全文 hash 所有文件。

事件在旧代的时间/模型与新代原文定位分开存；匹配要有来源/继承作用域和一对一序列证据，不能只按 offset、ordinal、时间或 Token 相同去重。旧事实保留不强制有新定位；定位无效不阻断数值查询。计数重置段与首次累计种子不可当普通追加 delta。

最小共同验收样本：旧账有 A=80、B=20；重写后原文只剩已证明同一笔的 B=20，并新增 C=5。有效累计必须是 **105**，不能是重建覆盖后的 25，也不能是旧总数加新文件总数的 125。再次打开仍为 105，随后追加 D=7 变为 112；A 的正文可标为不可用，但其原时间与数值仍可查询。若后来有明确证据证明 A 里的 10 是重复计数，作带证据修正后为 102，而不是冻结成永不变化的 112。
