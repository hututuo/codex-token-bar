# 二级额度侧栏按内容高度布局

用户确认：仅预留一个TPS模型条目的余量；新增一条先使用上下余量，超过才平滑拉伸外框。

- Swift与Tauri均测量正式侧栏内容和TPS模型条目高度。每次收起后，以内容+上下各12pt+一条TPS高度准备下次展开。
- 当前展开期间，内容变高先消耗已有余量，装不下时只增到所需高度；内容减少不立即来回缩框，收起时重算。框内仍居中，余量自然由上下两侧提供。
- 普通TPS数字变化不改变几何；Swift Preference和Web ResizeObserver仅在实际尺寸变化时上报，Web测量按RAF合并，不增加轮询/扫描/数据库写入。
- 继续使用原生窗口动画（展开/增高约440ms，收起约240ms，减少动态效果直接到位），从当前帧重新定向。滚动视口在动画期间采用最终目标高度，避免内容随裁剪每帧重排。
- 保留稳定绘制画布，680pt是内部最小值而非可见栏高度；大内容只在需要时扩容。窗口按所选屏幕工作区与DPI限制，超过可用高度后滚动承接。拖动释放/换屏沿用相同目标高度。
- 高度状态仅内存保存；不改SQLite、扫描、账本、测速口径或原用户数据。

验证：Swift侧栏+图表71项通过，其中生产原生侧栏动态新增1→2→3模型实际窗口520→520→563pt；前端75项通过、生产构建通过；Rust27项通过。真实浏览器正式组件555→555→600 CSSpx，两端分别按各自真实字体测量，不强行使用固定条目高度。

Windows x64 adapter check通过，覆盖真实生产canvas_metrics/canvas_geometry/canvas_windows；不替代整机Windows应用构建、placement模块的Windows类型检查或多屏视觉验收。ARM64本轮未做新构建。macOS本机安装验收见外层runs/20261022-sidebar-content-height/回执；本补丁不关闭原先Windows左屏拖不出的真实多屏反馈。
