## 设计与口径

- **Codex 是主体。** 默认显示保留原样。其他客户端读取/显示默认关闭；发现本地程序或残留记录目录时提示“发现”，不把残留记录冒充当前安装。手动指定路径和有历史账本的客户端仍可管理。
- **合计是 Token 合计。** 输入 + 输出；缓存和思考按其子集字段单列，不重复相加；不把订阅额度百分比相加，不推算未知余额或收费。侧栏是累计已记录量，主页面是所选区间量，标签分开。
- **图表是可比较的时间桶。** 24h 为最近24个UTC小时桶，7/30天为最近7/30个UTC日桶，包含当前未结束桶；不是精确滚动24小时积分。分色堆叠或合并总量，缺失记录不插值。范围以当前时间推进，不能停在旧账本写入时间。Codex 图表未就绪会提示合计可能不完整。原主页面其他费用/统计仍为 Codex，不混入未知计价。
- **独立配置。** 客户端卡片在 Codex 原有模块之后，组内顺序可调；Codex 原模块仍用已有排序配置。菜单栏/托盘设置沿用 cf7dbb23；Windows 托盘不支持分段颜色。旧版单独 Claude 额度显示设置继续兼容。
- **额度不增加网络。** 统一提供者只投影已有观测。Claude 缓存10分钟有效、窗口到期失效，缺失显示未接入，损坏/过期显示不可用；给出手动配置现有 `claude-monitor --statusline` 的说明，不自动安装或改配置。缓存不带账号，必须显示“最近 Claude 进程，未绑定账号”。联网额度未实现、保持关闭。

## 存储、性能与数据保护

- 数据仍在独立 `multi-client-usage.sqlite`，不是新建 Codex 账本，更不覆盖 Codex 原记录。schema 2 只加 `client_usage_by_time(timestamp,client)`；升级备份覆盖已提交 WAL，旧事件、修订和断点保留；拒绝高版本降级写入。
- 原始来源删除/关闭扫描后，已入账数据保留。全部关闭且从未建库时不建库、不扫描提供方日志。
- 检测仅已知路径/有限 PATH 元数据探测，不执行 CLI、不递归扫全家目录。Rust 检测缓存60秒；Swift 跟随唯一60秒刷新循环。首次大历史继续有界分批增量。
- 趋势 SQL 使用时间索引，最多读取最近30天的3605个小时聚合桶；前端只绘制24/7/30桶，每客户端一组。额度视图复用同一缓存，没有新增每卡片定时器。Tauri 每个可见 WebView 共享一次刷新，隐藏页面不扫描。
- 侧栏合计新增精确 `totalTokensValue`，不从“1.2M”文本反算；微小增量即使显示文本不变也不丢失。TPS 原值、算法、模型归属、上传协议均未改动。
