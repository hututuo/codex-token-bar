# 失效会话路径不阻断历史统计

## 问题与统一契约

Windows 0.9.4 用户的 `state_5.sqlite.threads` 保留了多条未归档会话的旧 `rollout_path`。文件不存在时，跨平台端将其作为扫描失败，阻断仪表盘和用量汇总；Mac 原生端已跳过确认不存在的来源。该跨平台阻断规则至少在 2026-09-02 的 `4efd97f7` 中已存在，早于 2026-10-04 的压缩读取支持 `3a3d538c`；v0.9.2、v0.9.3 均含此规则。

统一处理：

- 已入库的会话，即使原文删除、移动或不可再发现，历史数值与稳定事件身份仍保留；继续发布其他正常来源的新增用量。
- 不修改 Codex 的数据库或会话文件，不清空/重建用户索引，也不添加数据库迁移。
- 原普通 JSONL 缺失时先按既有逻辑查同名 JSONL.zst；两者都确认不存在才作为来源缺失，而不是扫描失败。
- 确认缺失须有可解析的现存父级，且当前所选 Home 仍可用。整个 Home 迁移后遗留的、已确认不存在的外部绝对路径也忽略；不因此读取外部原文或接纳外部来源。Home 不可用、权限/I/O 错误、损坏压缩文件、悬空链接不冒充删除，继续保留原有失败保护。
- 没有入库过且原文已经缺失的记录不能恢复准确用量；不使用 `threads.tokens_used` 制造新用量。
- 后续恢复文件按已有稳定身份和去重流程处理；归档移动不重计，fork 自有新增轮次继续统计。

跨平台修改覆盖预扫描候选和正式目录/active-rollout 枚举，包括枚举后、读取元数据前普通文件刚被移走的情形。缺失来源仍经过原有账本 missing/原文可用性处理；不改变事件保留、去重、归属或整轮原子提交算法。扫描期间已打开来源发生变化仍走原有重试/失败保护，不发布未经验证的半段内容。
