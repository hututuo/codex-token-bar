# 减少稳定刷新重复查询与旧暂存目录解析

本轮基于 `f2b51ab1`，实现上一轮定位的两项日常刷新热点，并合入独立 Astra Max 会话提供、由根会话验证的旧暂存目录优化。保留此前旧账恢复、TEMP 隔离、阶段池所有权、消息查询、账本对账和区间聚合修复；没有改变数据库 schema、账本版本或原有性能门槛。

## 三项改动

1. `record_successful_migration_retention` 使用已经准入的 Exact 连接读取迁移保留凭据，避免无凭据时每次重开 A 并加载约 2.5 万个对象。检查仍覆盖当前物理 A、初始化标记、运行状态、root 版本、Exact owner 和凭据版本/路径。owner 与凭据在同一读快照中校验，调用方已有事务由调用方管理。缺失凭据不缓存；晚到物理 manifest 继续走原冷准入路径。
2. `ensure_dashboard_aggregates` 在 schema、Exact generation、pricing revision 与实际投影签名均匹配时直接返回，避免为尚未发布的展示水位重复统计所有事件并取得空写事务。展示水位仍由原发布者写入，投影截断修复、版本兼容和 Summary→Full 保持原有路径。
3. `stage_pool/legacy.rs` 在一次冷目录扫描中复用同形 DDL 的规范化摘要。只接受精确生成的物理表名头和逐字相同、不含当前 owner 前缀的正文，最多 16 个、每个 32 KiB；其他情况继续原算法。缓存仅存活于一次扫描，不缓存行是否为空；列定义、外部依赖、owner、schema version 和实时行存在性检查保留。

## 已执行的验证

- 完整 Rust 库：1,784 通过、0 失败、14 项原有忽略；新增六个测试及旧候选相关回归实际执行。当前 CI Rust required-test 清单另用完整日志复核。
- 稳态聚合回归在原实现上实际失败为 `database is locked`；新实现可以与另一个 WAL writer 共存，零写入、零事件计数，展示水位不被冒写；损坏投影仍执行计数并修复。原失败证据保留在 `aggregate-before.*`。
- facade 回归覆盖另一连接写入晚到 receipt、未知 JSON/版本/路径、root 版本、owner、marker 改变以及调用方读写事务边界。早先两项失败来自测试初始化 marker 文件名，修正后定向及完整回归通过；失败日志保留。
- 非 `test` 生产构建的 16 个核心场景通过，包括原有 8 处强制中断、各 3 次重新打开。稳态 retention 连续 3 次零 reopen，原冷查询负对照实际 reopen 1 次。
- 新生产夹具在同一 bound handle 上先确认没有 receipt/manifest，再写入合法晚到物理 manifest，实际执行冷准入（4 次 open），登记合法 owner receipt 并切换 `.container-v1`；重复检查零 reopen。另两个 owner 的错误版本及错误路径均被拒绝；物理原文、发布 generation、17 tokens 保持，不生成伪成功迁移回执。
- 相关工作流、性能报告与执行记录脚本测试 30 通过；生产报告门禁测试 11 通过。新增负对照拒绝缺失字段、错误类型、零冷准入、非零稳态 reopen 和伪保留证明。
- 回填机制对照使用实际抽取的 `objects()`、原 binder 和同一 SQLite，在 32/128/512 个合成内存表上交替运行原实现与候选各 6 次；目录证据逐项相等，规范化次数从 32/128/512 降至 8，双方暖缓存仍为零次。最大规模 debug 中位数 25.128→1.610 ms，独立优化探针 11.661→0.719 ms。约 16 倍仅适用于这个小型冷目录扫描，不代表整次回填。
