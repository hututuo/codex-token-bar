# 多客户端热力图接入实施记录

状态：第一包已于2026-11-17完成云端检查、build 1022本机替换及真实界面点验。用户随后要求按原计划继续自动接入和测试；账号分段与缺失提供者取证继续进行。

## 接入结果

沿用原读取器、用量账本与额度历史，在展示边界复用原曲线的客户端/模型明细结构。新增日投影模块，不增加业务数据库、不迁移精确账本、不重写原始记录。

| 功能 | 实现路径与行为 |
| --- | --- |
| 日模型、金额、缓存 | Swift `MultiClientUsageLedger.dailyBuckets`、Rust `read_incremental_daily_buckets` 按客户端/本地日期/原始模型聚合；金额来自逐请求计价，保留原时点与缓存写入时长 |
| 热力图所有用量模式 | Swift `DashboardTokenActivity` / `HeatmapDayUsage`、React 同名组件 / `heatmapProjection` 接原热力图；每日、每周、累计、模型、费用、命中率保留已知信息并标出缺口 |
| 独立入口 | 热力图单独保存跟随主页/单客户端/汇总选择，不覆盖24小时曲线选择 |
| 额度日历史 | 原额度表派生365个本地日历日期；曲线仍读取原30天细节。Codex、Claude CLI/Desktop、Antigravity两池使用同一热力图 |
| 额度语义 | 独立选来源、Gemini或第三方池及5h/7d；日内真实采样均值、样本数、首末观测时间。选区仅平均有观测日并显示覆盖天数 |
| 已知与未知 | 同名模型保留客户端身份；已知金额不被未知部分抹掉；参考费用不进入已知合计；缺缓存字段不伪装为0%命中 |
| 缓存 | Swift按账本修订/分钟/本地时区重用日结果；Rust复用既有聚合缓存，补系统时区身份。移动或补充历史请求会失效旧日期；无变更读取复用缓存 |

## 既有功能边界

24小时/7天/30天曲线、主页统计、缓存排行沿用原接入；build 1021的Antigravity四等宽一行、侧栏紧凑小图标与完整小数布局保留。主页已有刷新周期驱动同一额度读取，视图切换不新增网络查询。Antigravity继续使用已获准的本机RPC，不加forceRefresh；localhost本身不构成客户端绝无上游请求的保证。

Claude的闲置缓存与重置待更新状态继续保留；API模式不制造订阅额度。普通用量/缓存文件在客户端关闭后仍可读取；Antigravity实时读取需要其本机服务存在，已有历史可以单独展示。显式隐藏与启用设置继续走原偏好入口。

外部额度目前按客户端/来源/池记录，尚无稳定账号字段。Claude文件导入会筛选当时最新组织，但旧持久化行没有组织身份，不能验证跨登录切换的整段历史都属于同一账号。现有“未验证当前账号”状态必须保留；账户分段属于尚未完成的兼容项，不把它写成已通过。Codex沿用原稳定账号身份与周期隔离。

Gemini CLI、DeepSeek CLI、OpenCode的用量接入可复用热力图；仍没有可靠本地额度提供者，额度模式说明缺少来源。这三类额度来源调查另行推进，不能由Token用量推造5h/7d额度。

## 数据库与性能核对

未修改表结构和数据库版本。日价格缓存只保留派生数组，重启可重建；历史记录是唯一事实来源。Swift投影在后台任务准备并检查取消，悬停与选区仅消费已准备的日数组。

需要明确：原 `effective_client_usage_events` 使用全局响应去重CTE。增量日计价会限制受影响日期，但底层去重仍可能读取更早的物理行；这里不宣称已经实现物理索引级增量扫描。Rust额度日聚合缓存每个日期的时区边界，避免每条样本重复计算。

回归加入3650条、365天夹具，记录首次、重复与增量日查询的耗时，并验证请求数/Token守恒、历史日期不变。本次没有单独测出各阶段峰值内存，也没有把UI动作耗时视为数据库扫描耗时。
