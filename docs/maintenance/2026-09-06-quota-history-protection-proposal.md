# 额度历史过滤与周期保护方案（待确认）

状态：**只提交方案，未实现。用户确认后才修改历史写入或图表规则。**

## 先分清两条链路

实时卡片、悬浮窗继续显示成功接口原值；历史过滤不能反向改写这份响应。内部统一使用 `usedPercent`，剩余值仅在展示时计算 `100 - usedPercent`。

历史链路保留接口观测，另生成“已接受的历史序列”。异常不能删掉原始证据，也不能冒充一次新周期。这里的“异常满额”指**剩余 100%，即 used=0**；used=100 是额度耗尽，不能仅凭数值为 100 就过滤。

当前本地 `cycle_id` 来自 `cycle_generation`，并非服务器周期 ID。Tauri 写入入口为 `core/quota_history.rs::record_for_identity_at`，周期判断和反弹处理也在该文件；图表清洗位于 `quota_history/series.rs::sanitized_rows`。Swift 对应 `QuotaHistoryStore`、`QuotaHistoryCyclePolicy`、`QuotaMonotonicNormalizer`。现有规则仍包含“used=0 且 reset 时间差超过约 5 分钟换期”和“下降至少 20 个百分点放行”，不能当成已实现以下方案。

## 推荐规则

按稳定账号、计划、limit、窗口分别处理；**5h 与 7d 完全独立**。

| 输入 | 历史处理 |
| --- | --- |
| 首次有效观测 | 建立基线，保留观测时间和原值 |
| `currentResetAt - acceptedResetAt > 1800 秒` | 确认新周期；首条 used 为 1% 或 2% 也接受 |
| 正好推进 1800 秒、倒退、缺失 | 不据此换期；绝不取绝对值判断 |
| 同周期 used 上升或不变 | 正常接受 |
| 同周期 used 下降，包括突然变 0 | 保留原始样本，暂列反弹候选，不立即改写可信历史 |
| 明确迟到或重复响应 | 不推进基线、周期或候选计数 |
| 失败、无稳定身份、无有效百分比 | 不生成可信用量点，不填 0，不延用上一账号状态 |

resetAt 的细小抖动不能不断移动 accepted anchor；新周期仍与确认过的 anchor 比较。观察时间越过旧 resetAt，但接口未提供可信新边界时，历史进入“边界待确认”；实时显示照旧。缺少 resetAt 的有效 used 观测可以保留，但不能独自建立新周期。重复回放同一响应不算多次确认；若接口没有服务器时间，不把客户端接收时间冒充服务端事件时间。

## 同周期持续反弹：请确认这一项

推荐采用**短时隔离、持续确认后记为修订**，不做永久单调钳制：

- 一次低值随后回到原水平：视为短时异常，历史投影忽略该低值，原始观测仍保留。
- 同一账号、同一 reset anchor 下，至少 3 次新的成功观测跨越 5 分钟持续低于此前基线：接受为“同周期额度修订”，不新建周期，不把下降算成负消耗。
- 条件不够或持续冲突：保持待确认，图表留出未确认区段，不虚构一条消耗曲线。

较保守的备选是“同周期任何下降都不接受，直到新周期”，但服务器发生真实修订时会长期显示错误历史，所以不推荐默认采用。

例：12%→0%→13%，resetAt 未推进：实时照显，历史排除中间 0%。12%→2%，resetAt 推进 1801 秒：新周期从 2% 开始。12%→8% 多次稳定且跨越 5 分钟：推荐作为同周期修订，图表分段，不计负消耗。

“新周期阈值 30 分钟”“候选确认跨度 5 分钟”“已有异常恢复观察窗 30 分钟”是三种独立语义，不共用常量。

## 落盘与旧数据

推荐第一版在**原额度历史数据库**内保留观测值与现有周期字段，可信序列由读取投影生成；不新增旁路数据库，不删除或全量改写旧历史。当前历史存在采样去重，不能承诺每次网络响应都已有一条原始记录；新策略必须确保异常及确认样本不会被常规去重吞掉。旧记录只能按其现存内容读取，不能追认成完整原始接口档案。

若要求跨重启永久保存每条观测的判断原因、accepted 值和候选状态，则需在同一表增加可空字段及规则版本，沿用现有兼容迁移。**这一存储扩展也须确认后才做。** 无持久状态版本的纯读取投影必须带足边界前的基线，不能让不同图表查询范围算出不同周期。

后续实施门禁：1800/1801 秒边界、倒退、非零重置、5h/7d 独立、迟到/重复、反弹恢复与持续修订、跨重启及查询范围一致、失败不填 0、实时卡片和悬浮窗原值直显。额度修订不能触发 token 历史重扫。
