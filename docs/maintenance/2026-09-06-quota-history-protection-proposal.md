# 额度历史过滤与周期保护方案（已确认）

状态：**2026-09-06 用户已确认实施，并明确新周期首条 used 不限于 1%／2%，允许全部有效百分比（0%–100%）。本轮为源代码实现，未替换运行应用或发布。**

## 先分清两条链路

实时卡片、悬浮窗继续显示成功接口原值；历史过滤不能反向改写这份响应。内部统一使用 `usedPercent`，剩余值仅在展示时计算 `100 - usedPercent`。

历史链路保留接口观测，另生成“已接受的历史序列”。异常不能删掉原始证据，也不能冒充一次新周期。这里的“异常满额”指**剩余 100%，即 used=0**；used=100 是额度耗尽，不能仅凭数值为 100 就过滤。

当前本地 `cycle_id` 来自 `cycle_generation`，并非服务器周期 ID。Tauri 写入入口为 `core/quota_history.rs::record_for_identity_at`，周期判断和反弹处理也在该文件；图表清洗位于 `quota_history/series.rs::sanitized_rows`。Swift 对应 `QuotaHistoryStore`、`QuotaHistoryCyclePolicy`、`QuotaMonotonicNormalizer`。本轮改动前的规则包含“used=0 且 reset 时间差超过约 5 分钟换期”和“下降至少 20 个百分点放行”，本轮已移除这些旧条件。

## 推荐规则

按稳定账号、计划、limit、窗口分别处理；**5h 与 7d 的策略参数和确认状态完全独立**。用户后续要求预留 5h 更宽松、7d 更严格的调整空间；本轮先保持两套初始参数相同。

| 独立策略参数 | 5h 初始值 | 7d 初始值 |
| --- | --- | --- |
| 新周期 resetAt 向前推进 | 严格超过 1800 秒 | 严格超过 1800 秒 |
| 新周期首条 used 上限 | 100% | 100% |
| 同 anchor 抖动容差 | 5 秒 | 5 秒 |
| 同周期修订确认次数 | 至少 3 次新观测 | 至少 3 次新观测 |
| 修订确认跨度 | 至少 300 秒 | 至少 300 秒 |

这些参数可以分别调整。本轮不把“一两分钟通常消耗不到 10%”写成硬性保证或门槛。

| 输入 | 历史处理 |
| --- | --- |
| 首次有效观测 | 建立基线，保留观测时间和原值 |
| `currentResetAt - acceptedResetAt > 1800 秒` | 确认新周期；首条 used 在 0%–100% 内均接受，例如 20%、80%、100% |
| 正好推进 1800 秒、倒退、缺失 | 不据此换期；绝不取绝对值判断 |
| 同周期 used 上升或不变 | 正常接受 |
| 同周期 used 下降，包括突然变 0 | 保留原始样本，暂列反弹候选，不立即改写可信历史 |
| 明确迟到或重复响应 | 不推进基线、周期或候选计数 |
| 失败、无稳定身份、无有效百分比 | 不生成可信用量点，不填 0，不延用上一账号状态 |

resetAt 的细小抖动不能不断移动 accepted anchor；新周期仍与确认过的 anchor 比较。观察时间越过旧 resetAt，但接口未提供可信新边界时，历史进入“边界待确认”；实时显示照旧。缺少 resetAt 的有效 used 观测可以保留，但不能独自建立新周期。重复回放同一响应不算多次确认；若接口没有服务器时间，不把客户端接收时间冒充服务端事件时间。

## 同周期持续反弹：已确认采用推荐规则

推荐采用**短时隔离、持续确认后记为修订**，不做永久单调钳制：

- 一次低值随后回到原水平：视为短时异常，历史投影忽略该低值，原始观测仍保留。
- 同一账号、同一 reset anchor 下，至少 3 次新的成功观测跨越 5 分钟持续低于此前基线：接受为“同周期额度修订”，不新建周期，不把下降算成负消耗。
- 条件不够或持续冲突：保持待确认，图表留出未确认区段，不虚构一条消耗曲线。

较保守的备选是“同周期任何下降都不接受，直到新周期”，但服务器发生真实修订时会长期显示错误历史，所以不推荐默认采用。

例：12%→0%→13%，resetAt 未推进：实时照显，历史排除中间 0%。12%→80%，resetAt 推进 1801 秒：新周期从 80% 开始。12%→8% 多次稳定且跨越 5 分钟：推荐作为同周期修订，图表分段，不计负消耗。

“新周期阈值 30 分钟”“候选确认跨度 5 分钟”“已有异常恢复观察窗 30 分钟”是三种独立语义，不共用常量。

## 落盘与旧数据

推荐第一版在**原额度历史数据库**内保留观测值与现有周期字段，可信序列由读取投影生成；不新增旁路数据库，不删除或全量改写旧历史。当前历史存在采样去重，不能承诺每次网络响应都已有一条原始记录；新策略必须确保异常及确认样本不会被常规去重吞掉。旧记录只能按其现存内容读取，不能追认成完整原始接口档案。

若要求跨重启永久保存每条观测的判断原因、accepted 值和候选状态，则需在同一表增加可空字段及规则版本，沿用现有兼容迁移。**这一存储扩展也须确认后才做。** 无持久状态版本的纯读取投影必须带足边界前的基线，不能让不同图表查询范围算出不同周期。

后续实施门禁：1800/1801 秒边界、倒退、非零重置、5h/7d 独立、迟到/重复、反弹恢复与持续修订、跨重启及查询范围一致、失败不填 0、实时卡片和悬浮窗原值直显。额度修订不能触发 token 历史重扫。

## 本轮实现选择与验证

- 双端分别提供 5h、7d 两套独立策略，初始参数相同，确认状态互不影响。reset anchor 仅在建立基线或确认新周期时设置；小幅抖动不会累积移动 anchor。
- 第一版使用原额度历史数据库及现有字段，不增加旁路数据库或判断原因字段。按稳定身份保存每次带新观测时间的成功响应，used/reset 原值保持；历史读取时生成可信序列。
- 这里的观测时间是接口读取流程的本地完成时间（Swift `updatedAt`、Tauri `updated_at`），不是服务端事件时间。写入不得以当前落盘时间替代缺失时间。相同或更旧的响应时间不推进状态；新时间戳下相同数值也保留，保证重启后 freshness 基线不倒退。
- 旧维护策略的重复观测删除、历史 anchor 回写以及 used=100 反向尖峰过滤已退出执行链路。旧行不批量改写；已丢失的历史原始值不能重建。
- 历史读取先取得该身份的完整保留序列，再计算可见时间范围。未确认下降输出空值；到达旧 reset 时间但未确认新边界时同样留空，不自动生成剩余 100%。前端不再次按 0%／100% 数值删除后端已接受的点。
- 保留原周期 ID 结构；同周期修订不增加 generation，不计负消耗。接口实时卡片与悬浮窗不经过历史过滤。
- 只读复核发现的共享额度归因旧周期条件已改用 7d 策略；有周期 ID 的可信历史允许同周期修订，消耗仅累计正向变化。仅有 legacy reset、没有周期 ID 的非单调观测仍不能产生最终他人用量归因，保留该安全门禁。
