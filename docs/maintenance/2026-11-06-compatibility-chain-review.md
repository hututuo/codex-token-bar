# 历次升级修复与当前候选的兼容性复核

日期：2026-11-06。复核基线 `eb5234fb`，产品最后实质改动 `b18fc185`，工作树 `f97f/codex-token-dashboard`。这是对原始故障、接续修复及最近性能改动的复核；没有新增产品补丁、调整版本、迁移正式数据库、安装、推送或发布。

结论：本次没有发现新的、可复现的正常升级兼容缺陷。已知旧账保全与恢复修复仍在当前祖先链中；当前 Rust 回归、生产入口和旧二进制到新二进制的中断接续均通过。**这不等于当前版本已完成双平台全部升级验收**：当前 Windows/完整历史 producer 矩阵尚未重跑，Rust 池 v2 也不支持直接退回旧二进制。

池升级的具体顺序仍是：取得 IMMEDIATE 写事务，重读身份与版本，核对完整已知 v1，创建索引并登记，更新模块版本/revision，核对 v2 后提交。失败时一起回滚；等待写锁期间另一进程完成升级时，后到者核对 v2，不重复升级。

发布桥接仍接受已知 v1/v2。原因是旧 pending 可能在首次 Pool 打开前进入发布，不能在调用者发布事务内被迫升级；正式事实与消费回执仍同事务提交，回收在提交后。未来版本3、坏合同、缺索引/错索引和错误身份不会被自动修造成“成功空池”。

## 仍须明确的边界

1. **升级兼容不等于直接降级兼容。** Rust池升级到2后，旧v1二进制会拒绝继续暂存/发布，这是本轮实测行为。当前没有自动降级工具。不能靠删索引、手改版本号或恢复旧整库备份绕过，后者可能覆盖升级后新增账。若要求“一键退回旧版仍能写”，它是尚未具备的功能。
2. **当前Windows与完整历史版本矩阵未重跑。** 上述云端历史成功只绑定28源码，之后的Rust改动由本次macOS当前回归和生产测试覆盖。尚不能宣称最新候选已双端全验收。当前完整App/安装包也未验证。
3. **未知/损坏格式仍保护性拒绝。** 缺必需表、坏清单、错owner、未绑定副本及未来版本不自动恢复。保留现场而报错是既定合同；“兼容”不表示能无损猜修任意数据库。
4. **既有未证实边界不扩大成新故障。** Swift旧sealed恢复副本会规范化DDL，之前的结构变异探针只证明恢复层接受某些结构，未证明最终导入/清理造成丢账；源码未变，本轮不把它列为新增回归。Rust `sqlite_sequence` 在首次投影视图被savepoint回滚后，需要重新经facade prepare，裸旧Statement不能保证继续复用；尚无已知产品调用触发。这两项保留原限定，不能据其声称已覆盖任意SQLite使用方式。

本次兼容性复核不改变[索引成本结论](2026-11-06-pool-index-write-cost.md)，也不将Swift长写锁等性能遗留说成兼容性缺陷已关闭。当前可收束的是本地已测兼容链；正式稳定版资格仍需绑定最终版本的跨平台/安装验证。
