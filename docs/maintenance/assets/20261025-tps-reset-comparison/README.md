## 重置标记的来源和精度

来源是本机 `quota-history.sqlite` / `quota_snapshots` 的原始保留记录，字段 `id`, `created_at`, `seven_day_used_percent`, `source`。三次均核对相同稳定账户身份（身份版本、Home、账户键、套餐、限制）；原始来源均为 `swift`。只导出数值和行 ID，不导出账户身份或凭据。

图中蓝线是**首次观测时间，不声称是服务器实际执行重置的精确时刻**。蓝色阴影是保留前后记录之间的保守定位区间：A约2小时15分、B约1小时2分、C约61秒。没有拿服务器给的 `seven_day_resets_at` 当成实际重置时刻。

10/24 04:28:38.137857（行66050）已用仍为0%，只是下次计划时间从10/31 02:33附近改到10/31 04:28附近，未作为另一次重置。目标账户在10/21和10/22未找到符合明显下降阈值的边界；另一个账户的下降没有混入这三次额度序列。

**正文测速记录本身没有逐样本账户字段**，因此这里是本机 Home 的模型速度与某一账户额度事件的时间对齐，不能证明每条速度都属于该额度账户，不能推导额度回升导致了某种速度变化。这里只检查额度序列内没有突然回弹迹象；没有重新运行完整费用账本撤销投影，也不据此新增周期结论。

## 三种图的固定规则

- ①：30分钟中心滚动加权均速，至少3个有样本的桶、6段正文；边缘窗口虚线。相邻观测间隔超过15分钟就断开，不跨长空档。历史图使用未来15分钟信息，不能直接充作实时瞬时值。
- ②：独立于额度标记的耗时加权误差惩罚分段。面向长时段，每个可画段要求至少30分钟、6个非空桶、6段正文，临近段均速至少相差10%；不满足持续性门槛的采样岛只画底部覆盖刻度。这里是候选统计阶段，没有统计置信度承诺。没有把蓝线强制当成分段边界。
- ③：固定30分钟区块的五分钟桶 TPS P25–P75与中位线，至少3桶、6段。不是逐条正文分布、不是置信区间，也不是加权均速。
- 每行三图时间范围和Y轴相同；各行Y轴可不同，不从0强制起步。范围由实际展示的汇总量决定；原始未被展示的尖峰仍在JSON，未从数据库删除。淡灰底部刻度展示所有有样本的原始五分钟桶。

## 可得结论与限制

A是最适合观察持续阶段的窗口。观测线前后全窗加权均速仅差约-0.4%，但局部有多个升降阶段；不能概括为“额度重置后持续从50下降到40”。

B在观测回升前最后一个正文样本结束于10/23 23:00:21，之后第一个正文样本从10/24 04:35:05开始。图上真实留空，不能把前7段和后21段的均速差作为重置瞬间变化。后侧仅半小时左右的集中样本，不能推广为数小时的持续速度。

C在13:40:12结束的样本后，直到15:40:51才出现新的正文样本开始。14:10附近没有测速证据；右侧10段不等于重置后近两小时持续有数值。不要用少量样本制造“重置提速”的结论。
