# 活动曲线、模型费用与预览数据隔离

## build 968 问题与修复

- 活动图查询会保留比显示窗口更早的桶，Swift Charts 又未裁剪绘图区，造成曲线越过左侧边界。新投影在一次固定的时间范围内过滤、分段，再交给图表；Swift/网页均裁剪绘图区，不把窗外数据压到边缘。
- 旧 `segmentID` 在每次下标访问时重新读取时钟并筛选数组。跨桶过期边界时数组变短会触发越界；2026-10-28 23:25 的崩溃栈确认了该路径。新投影直接携带段号，不再用旧下标重新筛选。
- 汇总模型费用保留真实客户端和时间范围。今日优先用紧凑摘要的模型行；暂未发布时可以复用当前日的精确索引模型桶，不拿累计明细代替。明细尚未到齐但已知有 Token 时显示同步状态，不宣称零使用；缓存键包含模型桶覆盖和索引代次。
- 共享 A 库后，逐文件暂存检查曾重复执行全库 `quick_check`。现仅对当前暂存分区的四张表做同等校验；旧独立暂存仍做全库校验。正式已发布索引的完整性策略不变。实机复查又发现，同一暂存的多个 SELECT 各自打开连接会反复解析整个 A 库结构；验证现放在同一只读连接、同一读事务内，避免重复加载，并让校验看到一致快照。
- Claude 最新模型保留在前，旧 Opus/Sonnet/Haiku/未分类模型合在同一个“Claude 其他”紧凑分组，原始模型 ID、Token 和费用不变。

## 本机模拟记录修复

预览实例使用独立偏好设置，却曾共用正式多客户端 B 库。三份明确标记为 simulated 的预览日志写入了正式投影，共 1,357 条；真实本地 Claude 记录为 201 条，ID 无交集。

本次逐条核对来源、记录键和摘要后，将模拟行移入同一 B 库的 `client_fixture_quarantine`。完整行 JSON、原始修订账本和修复前完整 SQLite 备份均保留；不按模型名或日期批量删除。核对结果为：真实 201 条完全未变，模拟 1,357 条可恢复，修订 1,558 条保留，近七天 Claude 为 0。私有证明清单及本机路径只放在忽略的 `scratch/build969-fixes`，不提交仓库。

`scripts/quarantine_usage_fixture_rows.py` 默认只验证，`--apply` 才执行；必须提供每条记录的精确键及完整行摘要，任一不匹配就回滚。它不自动扫描或修复其他用户的库。

原生预览 bundle 的 B 库改放在独立 `Previews/<bundle-id>` 下；正式版路径不变。Tauri 显式模拟模式的库与设置也分开，发布构建忽略模拟环境标志。活动速度使用同一 B 路径，不另造第三个业务库。
