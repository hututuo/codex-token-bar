## Current state

### 额度历史的长期契约

以下是已经落地的行为，不要在 v0.9.2 中退回旧启发式：

- 额度历史永久保留，不按 45 天或其他年龄删除。
- 5h 与 7d 各自独立维护周期代次和重置锚点。
- 新周期只在同一次观测同时满足以下条件时成立：
  - 规范化额度正好回到 100%，即 `usedPercent == 0`；
  - 当前重置时间与已接受锚点的绝对差值严格 `> 300` 秒。
- 恰好 300 秒不换周期；300 秒指重置时间差值，不是要求额度维持 100% 五分钟。
- 稳定确认是连续成功观测的首尾真实跨度至少 5 分钟、至少两次观测，并且整段重置时间 `max - min <= 5` 秒；最后 1～2 秒摆动仍算稳定。
- 每次只漂移 4 秒但累计范围超过 5 秒时，不能误判稳定。
- 额度从 100% 变为 99% 等真实使用不打断重置时间稳定判断；任何真实额度变化值和原始时间戳都永久保留。
- 小于等于 5 秒的纯重置噪声不新增普通历史行；超过 5 秒先保留，稳定确认后只压缩没有信息价值的重置时间冗余。
- 不新增网络请求、每秒计时器或系统唤醒；稳定候选只随现有成功额度刷新更新。
- 启动、唤醒和成功刷新只做 O(1) 到期检查；到期的维护在后台事务中执行。
- Swift 只写 `CodexTokenBar/quota-history.sqlite`，Tauri 只写 `CodexTokenBarTauri/quota-history.sqlite`；对端库始终只读。
- 周期判断使用持久化周期 ID，不要恢复“重置时间相差 120 秒就视为同周期”的旧逻辑。

## What was tried

这些历史失误或排查结论需要避免重复：

- 曾经用“重置时间差 120 秒”猜周期，无法可靠区分云端时间漂移和真实换期，已经删除。
- 旧讨论出现过“稳定 30 分钟”，最终已明确并实现为 5 分钟；不要复活 30 分钟规则。
- 不能把“100% 保持五分钟”当成换期条件，用户可能在重置后立刻从 100% 用到 99%。
- 折线图与气泡多次出现“源码改了但用户看到没变”，根因之一是候选包/运行实例错位；以后先证明 live bundle 和 PID。
- Swift 与 Tauri 的交互实现不同，持续打小补丁容易破坏候选线、区间选择、气泡位置和启动滚动位置；涉及图表时先读完整状态机和布局链路，再改共享尺度或事件处理。
- Windows 正式构建在 HTTWIN 上完成；PowerShell 远程命令成功码应使用 `$LASTEXITCODE` 或 `cmd /c ... & echo` 等可靠方式，不要把 `status` 当成 shell 内建判断。
- 发布定位文件必须在公开发布前后都回读核对；本地资产存在不代表 GitHub Release、appcast 或 updater metadata 已经生效。
